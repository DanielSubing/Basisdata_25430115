## 4. Jawaban Titik Analisis
Titik Analisis 1–4
Mengapa akun root tidak boleh digunakan untuk operasional harian aplikasi?

Akun root adalah superuser dengan kekuasaan mutlak tanpa batasan privilege. Jika koneksi aplikasi web dieksekusi langsung memakai root dan aplikasi tersebut memiliki celah keamanan (misalnya kerentanan SQL Injection), penyerang dapat langsung membaca, memodifikasi, menjatuhkan (drop) seluruh basis data lain di server, atau bahkan mengakses sistem berkas server lokal.

Apa perbedaan antara set karakter utf8 biasa dan utf8mb4 di MariaDB/MySQL?

Implementasi utf8 lama di MySQL/MariaDB (alias utf8mb3) hanya mengalokasikan ruang simpan maksimal 3 byte per karakter, sehingga tidak mampu menampung karakter Unicode 4-byte penuh. Set karakter utf8mb4 mendukung 4 byte secara utuh, menjamin karakter multibahasa non-latin kompleks dan simbol modern/emoji tersimpan aman tanpa teks terpotong atau rusak.

Mengapa pemisahan akun operasional (seperti mhs_<3d>) dan akun pengembang (dev_<3d>) penting dalam lingkungan kerja?

Pemisahan akun menerapkan prinsip pemisahan wewenang (separation of duties). Akun dev_115 dialokasikan untuk kebutuhan rancang bangun skema struktur tabel (DDL), sedangkan akun operasional/aplikasi hanya diberikan hak manipulasi data (DML) pada tabel tertentu. Ini mencegah risiko perubahan struktur skema yang tidak sengaja dilakukan oleh skrip aplikasi biasa.

Apa fungsi mode cookie pada phpMyAdmin dan apa pengaruh sql_mode yang ketat?

Mode autentikasi cookie mewajibkan pengguna memasukkan nama pengguna dan kata sandi pada halaman login per sesi browser; kredensial tidak disimpan mentah (plain text) di dalam berkas konfigurasi web. Sementara parameter sql_mode yang ketat (seperti STRICT_TRANS_TABLES) memaksa MariaDB menolak data yang tidak valid atau melebihi kapasitas kolom, alih-alih sekadar memotong atau mengubah datanya diam-diam.

Analisis Perbedaan Kode Galat (Error Code)
Galat 1044 (ER_DBACCESS_DENIED_ERROR):

Pesan galat: Access denied for user '...' to database '...'. Terjadi saat proses autentikasi login berhasil, namun pengguna mencoba memilih (use), membuat (create), atau membaca basis data yang sama sekali tidak diberikan izin akses padanya.

Galat 1045 (ER_ACCESS_DENIED_ERROR):

Pesan galat: Access denied for user '...' (using password: YES/NO). Terjadi pada tahap awal autentikasi (pintu masuk) akibat kombinasi nama pengguna, host asal, atau kata sandi yang dikirimkan tidak cocok dengan catatan akun pada tabel mysql.user.

Galat 1142 (ER_TABLEACCESS_DENIED_ERROR):

Pesan galat: ... command denied to user '...' for table '...'. Terjadi ketika pengguna sudah berhasil masuk dan memiliki akses pada basis data, namun mencoba mengeksekusi jenis perintah tertentu (misalnya CREATE TABLE, DROP, atau UPDATE) yang hak izin perintahnya (grant) tidak diberikan pada tabel terkait.

## 5. Hasil Latihan dan Modifikasi
Pembuatan Akun Tamu dan Uji Galat 1142:

Sesuai instruksi Bagian E.1, dibuat akun tamu_115 yang hanya diberikan hak perintah SELECT pada basis data kopma_115. Ketika akun tamu_115 mencoba mengeksekusi perintah pembuatan tabel baru CREATE TABLE uji (id INT);, MariaDB memblokir proses tersebut dan memunculkan galat 1142 (CREATE command denied to user 'tamu_115'@'localhost' for table 'uji'). Hal ini membuktikan bahwa pembatasan hak pada level perintah (command-level privilege) berfungsi optimal.

Skrip SQL Bersifat Idempotent:

Sesuai Bagian E.2, berkas p01_lingkungan_115.sql disusun menggunakan klausa proteksi CREATE DATABASE IF NOT EXISTS dan CREATE USER IF NOT EXISTS. Skrip ini telah diuji dijalankan berulang kali melalui terminal dan berhasil tereksekusi tanpa menghasilkan eror duplikasi objek.
